# v1.2.0 设置面板 + 聊天区召回滑块 — 设计与验收说明

> 本文件是 v1.2.0 的详细设计说明与测试机验收清单（详细说明集中放 docs/，README 只留简要介绍）。
> 与实现落地后的最终形态一致。
> 契约真源：`starmemory-dsh-port/dsh-skills/skills/make-dsh-plugin/references/07-settings-panel.md`
> （基线 0.2.0-rc.2，0.2.1-rc.1 复核）+ `starmemory-dsh-port/DSH聊天界面3080-自定义控件滑块实现经验.md`
> （对照 `dsh-nekowhale-stickers` 反推，真机验证可渲染）。

## 1. 目标

1. **设置面板**：召回开关 + 档位（0-6）进 Plugins 页卡片（`plugins.item`）。
2. **聊天区召回滑块**：常驻聊天界面（3080）右上角（`shell.overlay`），贴合原版召回体验。
3. **维护/调试日志**：`~/.starmemory/plugin.log`（JSON Lines，轮转），可 grep 定位问题。
4. 本版**不做美化**，只做基础核心功能，确保稳定、结构正常、可调试维护。

## 2. 数据通道与权威规则

- 单一事实源：Config schema 三个 volatile 叶（`recallEnabled` / `recallEffort` / `recallPanelConfigured`），经 `configForms.get('starmemory-dsh')` scope 读写。
- 滑块与卡片不直接通信，都是同一 scope 的两个视图；任一侧写入 → 宿主 `loader/volatile-update` → Node half 重读同步进 recall-runtime.json → 另一侧快照更新。
- 权威规则：`recallPanelConfigured=true` → Config 为持久权威（apply 与 volatile-update 时同步进 recall-runtime.json）；`false` → recall-runtime.json 为准。**任何 client 写入都置 `recallPanelConfigured=true`**。
- 写路径：单字段优先 `scope.set(key, value)`；多字段（如拖到 0 = 关闭）优先 `scope.mutate([{type:'set',path:[key],value}], revision)`，失败回退逐字段 `set`。
- React #185 防线：按 `scope.getSnapshot()` 对象身份缓存派生状态；订阅优先 `scope.subscribe`，无则 500ms 低频轮询兜底。

## 3. 文件与结构（落地最终形态）

```text
starmemory-dsh/
├── index.mjs                 # 命名导出 name/inject/apply/Config；apply(ctx, config)
│                             #   静态 import z（fork schemastery）；volatile-update 重读同步
├── client/index.js           # client half：手写 CJS 单文件（__ModuleLoader__ 包装）
│                             #   inject ['slots','configForms']；两个 slot 各自独立 try/catch

└── test/config.test.js, test/log.test.js   # 新增单测
```

### 落地偏差（相对整体设计文档）

| 设计文档 | 落地 | 原因 |
|---|---|---|
| client-src 多文件 + esbuild 构建 + 产物入库 | **client/index.js 手写 CJS 单文件，无构建步骤** | 消除 esbuild/seed/banner/外部 require 重写等接缝；client 报错即白屏，接缝越少越稳 |

| `build:client` 脚本 | `check:client`（node --check 语法校验） | 无构建需求后，改为语法门禁 |

## 4. 门禁命令（仓库根）

```sh
npx --no-install esbuild index.mjs --bundle --platform=node --format=esm --outfile=NUL --external:@deepseek-ai/*
node scripts/check-schema.mjs        # 26 工具 schema
node scripts/check-client.mjs        # client 语法校验
```

注意：`index.mjs` 加静态 `import z` 后 esbuild 门禁**必须带 `--bundle --platform=node --external:@deepseek-ai/*`**（仅 --external 无 --bundle 会报 Cannot use external without bundle）。

## 6. 已知风险接缝（本机无 dsh，测试机验证）

1. `configForms.get(ns)` 的 scope 是否有 `set` / `mutate` / `subscribe`（本实现全部做了功能探测与回退）。
2. seed 模块表 id `@deepseek-ai/dsh-client-ui-primitives` 与 `Switch` 导出名（07 §3 实测列了 Switch）。
3. `loader/volatile-update` 事件名（07 §2 照抄）；`ctx.on` 存在性已做探测，缺失则降级为日志警告。
4. `shell.overlay` 渲染位置与 fixed 坐标（nekowhale 验证过槽存在；top/right 可能需按右上角现有控件微调）。
5. `@deepseek-ai/schemastery` fork 的解析（与 dsh-tools 同理，由 profile 闭包注入；手动安装需补链接）。
6. `dsh.client.external` 字段形状（nekowhale 用 `inject` 字段；04 契约用 `external`——以测试机为准）。

回退边界：所有接缝问题收敛在 `client/index.js` + `package.json` 的 `dsh.client` 字段，不动 Node half 契约与 26 工具。

## 7. 视觉（v1.2.3 终末地工业风重写）

> v1.2.1 迷你星空+像素流星、v1.2.2 彩虹渐变——v1.2.3 起整体换「终末地工业风」（`endfield-ui` skill），滑块保留彩虹/发光/循环流星（用户指定例外），按工业风外壳融合。

### 7.1 固定规则（endfield-ui，六条法则落地）

- **唯一强调色 `#FFFA00`（信号黄）只做填充**：选中档位块 = 黄填充；不用于描边/文字（浅色主题）。
- **切角 = 可点击**：档位按钮 `linear-gradient(-45deg, transparent calc(var(--ef-cut) - .5px), var(--fill) var(--ef-cut))`；滑块容器 `clip-path` 右下切角。`radius` 一律 0。
- **细线分区**：卡片用 `--ef-rule` 1px 发丝线分 section。
- **宽体大写英文 + 粗体中文**：眉标 = 上行小号大写宽字距英文（`// RECALL`、`// OBSERVE`）+ 下行粗体中文；Saira 字体本版不打包（DSH 静态资源服务未验证），用近似栈（Saira/Exo 2/Chakra Petch/Rajdhani/Arial Narrow）+ 宽字距 + 字重模拟。
- **真实数字 tabular**：档位 `No.03 / 06`（`font-variant-numeric: tabular-nums`），档位按钮带两位编号前缀。
- **机械动效**：填充条 `transition: width .22s cubic-bezier(.7,0,.2,1)`；无持续循环装饰动画（滑块流星为指定例外）。
- **红只给删除**：错误用黄块提示（`.sm-err` = 黄底 `#FFFA00` + 深字），不用红色。

### 7.2 聊天滑块（shell.overlay）：工业命令栏 + 彩虹流星

- **深色命令栏**：`#161616` 底 + `--ef-rule` 发丝边框 + `clip-path` 右下切角（`--ef-cut: 10px`），两主题都深（浮层独立成立）。
- **保留（用户指定例外）**：深空星野（纯 CSS 星点 box-shadow 点阵）、循环流星划痕（7s 无限，`prefers-reduced-motion` 时关闭）、彩虹填充层（`--sm-rainbow` 红→橙→绿→青→蓝→粉）+ 彩虹发光滑头。
- **眉标**：`// RECALL`（上行）+ `召回`（下行）；**真实档位**：`No.03` / `/ 06` 右对齐。
- 轨道：暗底像素分格（`repeating-linear-gradient`）+ 彩虹填充层（按档位宽度裁剪）+ 原生滑头三层结构。

### 7.3 设置卡片（plugins.item）：终末地工业风

- 卡片 token 随 `body[data-ds-dark-theme]` 切深浅（浅：纸 `#F4F4F2`/板 `#FFFFFF`/墨 `#161616`/墨2 `#5C5C5C`/线 `#D9D9D6`；深：板 `#222222`/墨 `#EDEDED`/墨2 `#A3A3A3`/线 `#353535`），信号黄两主题都 `#FFFA00`。
- 结构：`// RECALL` 召回控制 section（Switch + 档位按钮行 + 说明）+ `// OBSERVE` 观察面板 section（占位 = 斜线纹空态 + 完整句子）。
- 档位按钮 = 筛选块：`03 极轻` 两位编号 + 中文，选中 = 黄填充 + 深字（`is-on`），未选 = chip 底 + 墨2 字，均切角、radius 0。
- summary 视图（插件列表）用 `.sm-ef-eyebrow`（颜色走 DSH alias token，随宿主主题自动适配）；page 视图用 `.sm-ef-card .sm-eyebrow`（endfield ink token，随卡片主题）。

### 7.4 实现方式与不变

- 样式经 `<style>` 一次性注入（`ensureStyle`，id 幂等，apply 早期注入防首帧闪烁）；纯 CSS，无图片资源、无外部字体。
- 逻辑零改动（数据通道、权威规则、写路径、React #185 防线、白屏红线全部保留）。

## 8. 不变项

- 26 个工具、数据位置（`~/.starmemory/`）、SQLite 归档、bundle 安装方式均不变。
- 本版不加任何 npm 依赖；client 单文件无构建依赖。

### 9.2 稳健性修正（v1.2.4）

- 13-gotchas §4（环境事实）：宿主可能清理/覆盖注入 `<style>`，**关键样式用 JS 内联**。v1.2.3 全押 class 注入；v1.2.4 把非伪元素关键视觉内联（滑块定位/布局/配色/token、卡片布局），伪元素（星点/滑头/划痕动画）无法内联留 style 注入——style 被清时 UI 降级而非错位/消失。

### 9.4 打包配置实测修复（v1.2.6）

- **bug 1（files 漏 bundle patch）**：`dsh.bundle.patch` 指向的 `cordis.patch.yml` 不在 `files` 白名单 → npm/pnpm 按 `files` 过滤后发布包缺 bundle patch → DSH 校验 bundle 找不到 patch → 装不上/不收进 client bundle。v1.2.6 把 `cordis.patch.yml` 加进 `files`。
- **bug 2（client 用 external）**：`dsh.client.external` DSH 不认 → client half 不加载（面板/滑块都不出）。v1.2.6 改 `dsh.client.inject`。
- **bug 3（schemastery 找不到，非依赖配置 bug）**：安装方式问题——本地 link 装绕过 `plugin_manager`，依赖三字段留空导致 SDK fork 未注入。**正解 = 正规 `dsh plugin add`**（profile 闭包自动注入 fork）；不加 `dependencies`（DSH fork 有 `.volatile()`，公共 npm 版没有，加 dependencies 可能装到不匹配版本）。
- 新增门禁 `check:package`（`scripts/check-package.mjs`）：bundle patch 必须在 `files`、client 必须用 `inject`，锁死 bug 1/2 防回归。

### 9.5 首次安装面板空白修复（v1.2.7）

- **根因（测试机确诊）**：首次安装无 `settings.yaml` → configForms 命名空间未暴露 → `configForms.get()` 返回的 scope 存在但 `snapshot.status === 'unavailable'`（不是返回 null）。旧 apply 把 `!scope || !scope.getSnapshot` 当「拿不到 scope」→ 整体 `return` → 设置卡片根本没注册 → 面板空白；且卡片注册被 `whileServed([NS], ...)` 门控（namespace 未 served 不触发），双重挡住。
- **修复**：移除早期 return（scope 不可用只 warn）；卡片 `plugins.item` 无条件注册（移出 `whileServed`）；`createScopeBridge`/`makeCommit` 加 `scope &&` 守卫 + try/catch（null scope → status 'unavailable'）。组件侧已具备降级（滑块 `unavailable` → return null、卡片 `disabled`）无需改。
- **关键设计**：卡片是首次配置入口，必须无条件注册；`unavailable` 态由组件内降级处理（禁用/占位），不 gate 在 configForms 可用性。

### 9.6 依赖版本漂移修复（v1.2.8）

- **根因（测试机确诊 bug #4）**：插件 `Config` 用 `z.boolean().default().volatile()`，但 `dependencies` 未声明 `@deepseek-ai/schemastery`（假设 SDK 由 profile 闭包注入）。pnpm hoisted 把全局 schemastery 定成 **3.18.1**（无 `.volatile()`），插件解析到旧版 → `TypeError: volatile is not a function` → host 激活失败；DSH 本体用 **3.19.0**（有 `.volatile()`）。
- **修复**：`dependencies` 加 `"@deepseek-ai/schemastery": "^3.19.0"` 强制解析到 ≥3.19.0（有 `.volatile()`）；`check:package` 门禁加第三条（schemastery 必须声明且可达 ≥3.19.0，防回归）。
- **为什么保留 `.volatile()`**：它是 live-sync 关键（panel 改值 → `loader/volatile-update` → 同步 recall-runtime.json）；改用非 volatile 会让配置变更走 re-mount 而非 volatile-update，live-sync 降级。
- **为什么不加防御回退**：`.volatile()` 缺失是「依赖未声明」这一根因的表征，应**大声失败**（`volatile is not a function` 一眼定位）而非静默降级为难以排查的 subtle bug；门禁从源头锁死。

### 9.7 激活总开关修复（v1.2.9）

- **根因（测试机确诊 bug #5）**：`index.mjs` 的 `inject` 写了 `['tools', 'effect']`，但 **`effect` 不是可注入服务，是 ctx 自带方法**——DSH 把 `'effect'` 当要注入的服务去等 → 等不到 → **host 永远 pending 不激活** → 26 工具/Config/client 全没起来 → 面板空白。铁证：bili-whale 用 `ctx.effect()` 不声明 `effect` 也能激活；starmemory 声明了反而 pending。
- **修复**：`inject = ['tools']`（删 `'effect'`；`ctx.effect()` 调用不动）。注释改正确语义（effect 是 ctx 方法，不能写 inject）。
- **门禁**：`check:package` 加第四条——index.mjs 的 `inject` 不得含 `'effect'`、必须含 `'tools'`（防回归）。
- **教训**：`inject` 只列**真正的 ctx 服务**；ctx 自带方法（如 `effect`）绝不声明（否则 DSH 等一个永不到来的服务）。
